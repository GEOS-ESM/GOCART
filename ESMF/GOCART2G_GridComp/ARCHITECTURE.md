# GOCART2G_GridComp: architecture

**Audience:** coding agents and developers working on the GOCART2G aerosol gridded component and its children, `Process_Library` and `GA_Environment`.
**Describes:** the MAPL3 line, branch `release/MAPL-v3`.
**Verified against:** `GOCART` @ `96b3c9a` (2026-11-06).
**Placement:** as in the GEOSgcm fixture (`components.yaml` @ `f50622d`; repository `GOCART`, mounted at `src/Components/@GEOSgcm_GridComp/GEOSagcm_GridComp/GEOSphysics_GridComp/@GEOSchem_GridComp/@GOCART`).
Other fixtures (for example GEOSadas, GEOSldas) may place this repository elsewhere; paths inside this repository do not change.

Paths are relative to the GOCART repository root. Up: [repository architecture](../../docs/ARCHITECTURE.md), [agent rules](../../AGENTS.md), [decisions](../../docs/decisions.md), parent repository `GEOSchem_GridComp` (`../../../docs/ARCHITECTURE.md`), Physics (`../../../../ARCHITECTURE.md` in the fixture).

> **Build status on this line:** built; dust, sea salt and sulfate are ported to MAPL3. `ESMF/GOCART2G_GridComp/CMakeLists.txt` lists `GA_Environment`, `DU2G_GridComp`, `SS2G_GridComp`, `SU2G_GridComp` as subcomponents and comments out `CA2G_GridComp` and `NI2G_GridComp`; the parent module comments out the `use` and `add_children__` of CA and NI. The `CA2G_GridComp` and `NI2G_GridComp` sources are MAPL2 code kept for a later port. The component is built because `@GEOSchem_GridComp/CMakeLists.txt` calls `esma_add_subdirectories(GOCART)` ("Only GOCART is needed on release/MAPL-v3 (for GOCART2G_GridComp)"); its caller, `GEOS_ChemGridComp.F90`, is not compiled on this line. The regression cases (`ESMF/GOCART2G_GridComp/regression`) load the component from a YAML child list.

"Mie table" means a precomputed table of aerosol optical properties as a function of wavelength, relative humidity and size bin. "Klid" is the model level at the pressure lid above which aerosol is zeroed.

## 1. Purpose
GOCART2G simulates dust, sea salt, sulfate, carbonaceous and nitrate aerosol: emission, settling, dry and wet removal, chemistry, and diagnostics. It also builds the aerosol optical, microphysical and mixing-ratio services that Radiation, Moist, Surface, GAAS and GMI consume through the exported `AERO` state (`ESMF/GOCART2G_GridComp/GOCART2G_GridCompMod.F90`, `Initialize`). Each species is a separate child component; the parent only creates them, sums their exports and assembles the combined `AERO` state. On this line the parent and the DU, SS and SU children use the MAPL3 API (`use MAPL, only: MAPL_GridCompAddSpec, MAPL_GridCompAddChild, MAPL_GridCompAddConnection, MAPL_GridCompReexport, MAPL_GridCompRunChild, MAPL_GridCompGetResource, ...`).

## 2. Place in the hierarchy
- Parent: Chemistry (`GEOS_ChemGridComp.F90` in `GEOSchem_GridComp`) adds `GOCART2G` via `MAPL_AddChild` in the MAPL2 code of that file, which is not compiled on this line (see the repository architecture document, "Place in the hierarchy"). The component's entry point is `SetServices` in `GOCART2G_GridCompMod.F90`, wrapped by the external subroutine `GOCART2G_SetServices` at the end of the file (symbol `gocart2g_setservices_` in the regression `root.yaml`).
- Children: `create_instances_` calls `add_children__` for DU, SS and SU in that order; each instance gets `MAPL_GridCompAddChild(gc, child_name, setservices, hconfig, _RC)` with `hconfig` created from `<species>_instance_<name>.yaml` (`GOCART2G_GridCompMod.F90`, `create_instances_`, `add_children__`). The calls for CA and NI are commented out; `deactivate_instances__` then marks every CA and NI instance inactive and logs a warning when any was listed active.
- Instance names come from the `ACTIVE_INSTANCES` and `PASSIVE_INSTANCES` maps (keys `DU`, `SS`, `SU`, `CA`, `NI`) in `ESMF/GOCART2G_GridComp/GOCART2G_GridComp.yaml`, read from the component's `hconfig` (`setup_constituents_`, `setup_instances__`). Shipped values: one instance each for DU, SS, SU, NI; CA has `CA.oc CA.bc CA.br`; passive lists are empty. The parent asserts that at most one nitrate instance is active ("GOCART supports only one active nitrate instance").
- A name containing `data` makes a data-driven instance (`ESMF/Shared/Chem_AeroGeneric.F90`, `determine_data_driven`, called in each child's `SetServices`). On this line the data-driven branch of DU2G, SS2G and SU2G fails in `SetServices` with `_FAIL("data driver section has not been activated yet")` (DU2G; SS2G and SU2G say "data driven section"), so data instances cannot be created yet. The YAML lists `[DU.data]` and similar only as comments.
- The MAPL2 resource file `GOCART2G_GridComp.rc` is still in the directory; the ported parent reads the YAML and `CMakeLists.txt` installs only `GOCART2G_GridComp.yaml` of the parent's files.

## 3. Entry points
### Parent (`GOCART2G_GridCompMod.F90`)
- `SetServices`: registers Initialize and two run phases with `MAPL_GridCompSetEntryPoint`, `phase_name="Run1"` (`run1`) and `phase_name="Run2"` (`run2`); no Finalize is registered. Reads the wavelength lists with `MAPL_GridCompGetResource` and defines the ungridded dimensions `wavelengths_profile` and `wavelengths_vertint` (`MAPL_UngriddedDim`); the `use_threads` read is commented out. Builds child instances (section 2), declares the exports `AERO` and `AERO_DP` and the per-child `<name>_AERO` and `<name>_AERO_DP` items with `MAPL_GridCompAddSpec`, includes the ACG headers `GOCART2G_Export___.h` and `GOCART2G_Import___.h`, re-exports `PSO4` from the first SU instance with `MAPL_GridCompReexport`, and adds connections (section 4).
- `Initialize`: gets `geom`, `grid` and `km` with `MAPL_GridCompGet`; `add_aero_states_` adds each active child's `<name>_AERO` state into the parent `AERO` state and each child's `<name>_AERO_DP` fields into `AERO_DP` (DU, SS and SU only on this line; the CA and NI calls are commented out); adds named aliases (`PLE`, `RH`, `EXT`, `SSA`, `ASY`, optionally `MOM`, `monochromatic_EXT`, and the `sum_of_internalState_aerosol_*` fields) with `add_aero`; sets state attributes (`band_for_aerosol_optics`, `wavelength_for_aerosol_optics`, `n_phase_function_moments`, `implements_aerosol_optics_method`, among others); attaches ESMF methods (section 5); calls `setup_aerosol_activation`. A source comment notes that MAPL3 gives the state a default name (`StateNNN`).
- `run1`: runs phase `Run1` of every child except data-named ones (`MAPL_GridCompRunChild(gc, child_name, phase_name="Run1")`). No alarm check is present in the parent on this line.
- `run2`: first runs phase `Run0` (klid zeroing) of every non-data child; then zeroes the total exports; runs phase `Run2` of non-data children; then sums per-instance exports into `TOT*`, `PM*`, `PSO4TOT`, `TOTANGSTR`, `TOTABCKTOA`, `TOTABCKSFC`. `TOTANGSTR` requires 550 nm in the vertically integrated wavelength list (`VERIFY_(100)` otherwise). The backscatter exports require 532 nm. The CA and NI sums are commented out.
- On the MAPL2 line, Chemistry ran phase 1 and phase 2 of GOCART2G through numbered phases; on this line the caller of `Run1` and `Run2` is whatever hosts the component (the regression `root.yaml` lists `run_phases: - Run1` for GOCART2G).

### Child (same shape in the ported children DU2G, SS2G, SU2G)
Each child registers: Initialize, `Run1` (`run`), and, only if the instance is not data-driven, `Run2` (`run2`) and `Run0` (`run0`) (for example `DU2G_GridComp/DU2G_GridCompMod.F90`, `SetServices`).
- `run` is a dispatcher registered as phase `Run1`: it calls `run1` for a computational instance and `run_data` for a data instance.
- `run1`: emissions.
- `run2`: settling, dry deposition, wet removal, chemistry (SU) and diagnostics.
- `run0`: zeroes internal fields above the pressure lid (`Chem_AeroGeneric.F90`, `setZeroKlid`, `setZeroKlid4d`, `findKlid`).
- `SetServices`: `GA_Environment%load_from_config(gc)` reads the common keys; species keys are read with `MAPL_GridCompGetResource`; adds specs with the generated `*_Export___.h`, `*_Import___.h`, `*_Internal___.h` headers and `MAPL_GridCompAddSpec` for `TRADV`, `<name>_AERO` and `<name>_AERO_DP`.
- `Initialize`: reads `GOCART2G_DT` (default the heartbeat step), loads the Mie tables, builds the `<name>_AERO` state and `<name>_AERO_DP` bundle, attaches `aerosol_optics`, `monochromatic_aerosol_optics` and `get_mixR` methods and the `mieTable_pointer` attribute.
- Per-instance configuration: the instance file is `<X>2G_instance_<name>.yaml`, passed as the child's `hconfig` (`add_children__`). The MAPL2 fallback to `<X>2G_instance_<X>.rc` for an unlisted name is not in the ported parent code.

## 4. State
- Parent imports `DELP`, `AIRDENS`, `T`, `PLE` and imports of per-species diagnostics that are filled by the connections below; exports `PSO4TOT`, `TOT*` and `PM*` fields; no internal state (`ESMF/GOCART2G_GridComp/GOCART2G_StateSpecs.rc`, `schema_version: 2.0.0`). Generated headers `GOCART2G_Export___.h`, `GOCART2G_Import___.h`, `GOCART2G_GetPointer___.h`, `GOCART2G_DeclarePointer___.h` are included in the module.
- Additional parent exports: `AERO` (state), `AERO_DP` (field bundle), `<name>_AERO` and `<name>_AERO_DP` per instance, added in `SetServices` with `MAPL_GridCompAddSpec`; `PSO4` is re-exported from the first SU instance unless its name contains `data` (`MAPL_GridCompReexport`).
- Child state: ACG `*_StateSpecs.rc` (`schema_version: 2.0.0`; a `COND` column such as `scheme == 'ginoux'` in `DU2G_StateSpecs.rc` selects rows by configuration) for imports, exports and internal fields; hand-written additions in each `SetServices`. Internal fields are `MAPL_RestartOptional` and keep `FRIENDLYTO` `DYNAMICS:TURBULENCE:MOIST` in the spec. Each ported child also imports `TRADV`, a `MAPL_STATEITEM_SERVICE` item listing the advected tracers ("Replaces MAPL2's FRIENDLYTO=DYNAMICS"); `mapl3-porting-notes.md` in `SU2G_GridComp` says it takes effect once Physics is ported. Fields `DEEP_LAKES_MASK` (SS) and `H2O2_INIT` (SU) are not exported.
- Restarts: the parent's `GOCART2G_GridComp.yaml` sets `mapl: misc: activate_all_imports: true`, `activate_all_exports: true`, `restart: import: true` and `checkpoint: export: true, import: true`. Restart file names are not set in this repository.
- Couplings among siblings (parent `SetServices`, `MAPL_GridCompAddConnection` with `dst_comp="<self>"`): for each active non-data DU, SS and SU instance, the connections bring the instance's optical and mass diagnostics (for example `SSEXTTAU, ..., SSSMASS25`), its `<name>_AERO` state and its `<name>_AERO_DP` bundle to the parent. The MAPL2 connections that fed NI instance 1 from the first DU, SS and SU instances are commented out ("ACTIVATE ONCE NI HAS BEEN PORTED", `MAPL_GridCompAddConnectivity`).
- Couplings with other Chemistry children (imports from `CHEMENV`, `ACHEM`, `HEMCO`, `GMICHEM`; `AERO` to `GAAS`, `GMICHEM`, `CARMA`) are made in `GEOS_ChemGridComp.F90`, which is not compiled on this line; table in the repository architecture document, section 5.3. In the regression cases the imports are filled by a data component through `connections:` in `root.yaml` (for example `DU_SRC`, `WET1`, `LWI` from `DataForGOCART2G`).
- Per-thread workspaces: DU and SU hold `workspaces(0:num_threads-1)` indexed by `MAPL_get_current_thread`; SS has none (each child module, `SetServices`/`Run`). The parent's `use_threads` read and `MAPL%set_use_threads` are commented out ("Do we re-implement threading?"), so *Inferred:* threading is not configured by GOCART2G on this line.
- Data instances: not supported on this line (section 2).

## 5. The `AERO` state and its methods
Consumers call methods stored on `AERO`; they are not ordinary data. The methods keep the interface `(state, rc)`. All are module procedures in `GOCART2G_GridCompMod.F90`, attached in `Initialize` unless noted.
| Method | Does | Consumer (outside this repository) |
|---|---|---|
| `run_aerosol_optics` | Sums over the child states the extinction, extinction-weighted single-scattering albedo and asymmetry (and optionally phase function moments) that each child's `aerosol_optics` produced | Radiation (`GEOSsolar_GridComp/GEOS_SolarGridComp.F90`, `GEOSirrad_GridComp/GEOS_IrradGridComp.F90`); GMI photolysis (`@GMI/GMI_GridComp/GmiPhotolysis_GridCompClassMod.F90`, not built on this line) |
| `get_mixRatioSum` | Sums aerosol mixing ratios over the child states (header comment: sum of aerosol mixing ratio for GAAS) | `@GAAS/GAAS_GridCompMod.F90` |
| `serialize_bundle` | Returns a serialized field bundle of the aerosol fields of the child states (header comment) | `@GAAS/GAAS_GridCompMod.F90` |
| `get_monochromatic_aop` | Monochromatic aerosol optical properties summed over children (wavelengths from `aerosol_monochromatic_optics_wavelength_in_nm_from_LUT:`) | `@GAAS/GAAS_GridCompMod.F90` |
| `aerosol_activation_properties` | Mode-wise number, size, hygroscopicity for cloud-droplet activation; attached by `setup_aerosol_activation` in `ESMF/Shared/GOCART2G_AerosolActivationMod.F90`, not in the parent | Moist (`GEOSmoist_GridComp/aer_actv_single_moment.F90`; see the Moist document (`../../../../GEOSmoist_GridComp/ARCHITECTURE.md` in the fixture)) |
- `run_aerosol_optics` returns sums; the Solar consumer then divides to get single-scattering albedo and asymmetry (`SSAA=SSAA/TAUA`, `ASYA=ASYA/SSAA`) (`GEOSsolar_GridComp/GEOS_SolarGridComp.F90`, in the aerosol optics block). *Unverified:* that the infrared consumer does the same.
- Activation modes: 14 GOCART modes (`du001`-`du005`, `ss001`-`ss003`, `sulforg01`-`sulforg03`, `bcphilic`, `ocphilic`, `brcphilic`), or 7 MAMnet modes (`NUM_A_*`) when `USE_MAMNET` is true; `MAXCLEAN` (default 1e-9) and `CCNTUNING` are read with `MAPL_GridCompGetResource` (`setup_aerosol_activation`). The routine excludes NI children (`GOCART2G_AerosolActivationMod.F90`, `setup_aerosol_activation`).
- Child-level Mie lookups: `Process_Library/GOCART2G_MieMod.F90` (type `GOCART2G_Mie`, `QueryByWavelength_*`, `QueryByChannel_*`). Table files come from `aerosol_radBands_optics_file` and `aerosol_monochromatic_optics_file` in the instance YAML; wavelength lists are keys of the parent `GOCART2G_GridComp.yaml` (`wavelengths_for_profile_aop_in_nm`, `wavelengths_for_vertically_integrated_aop_in_nm`, `aerosol_monochromatic_optics_wavelength_in_nm_from_LUT`, `aerosol_photolysis_wavelength_in_nm_from_LUT`, `n_phase_function_moments_photolysis`).

## 6. Configuration
Only keys that change structure or scheme. File in parentheses. On this line configuration is YAML, read with `MAPL_GridCompGetResource` (scalars and lists) or from the component's `hconfig` (the instance maps).
- Instances: `ACTIVE_INSTANCES`, `PASSIVE_INSTANCES` (`GOCART2G_GridComp.yaml`). `use_threads` and `RUN_AT_INTERVAL_START` forwarding to children are not present in the ported parent.
- Time step: `GOCART2G_DT` (default the heartbeat step) in each child `Initialize`.
- Common to every child, read by `GA_Environment::load_from_config(self, gc)` (`ESMF/GOCART2G_GridComp/GA_Environment/GA_EnvironmentMod.F90`) from `<X>2G_instance_<name>.yaml`: `nbins`, `particle_radius_microns`, `particle_density`, `fscav`, `fwet`, `molecular_weight`, `fnum`, `pressure_lid_in_hPa`, `fwet_ice`, `fwet_snow`, `fwet_rain`, `wet_radius_thr`, `washout_tuning`, `wet_removal_scheme` (`gocart` or `ufs`; selects `WetRemovalGOCART2G` or `WetRemovalUFS`), `settling_scheme` (`gocart` or `ufs`; selects `SettlingSolver` or `SettlingSolverUFS`). `validate_config` asserts valid scheme names and rainout efficiency. The wavelength lists are read from `GOCART2G_GridComp.yaml`.
- DU2G: `emission_scheme` `ginoux` (default), `k14`, `fengsha`, plus scheme-specific keys; the scheme also selects which rows of `DU2G_StateSpecs.rc` are active (`COND` column); `point_emissions_srcfilen` (default `/dev/null`) (`DU2G_GridCompMod.F90`, `SetServices`).
- SS2G: `emission_scheme`, `sstEmisFlag`, `weibullFlag`, `hoppelFlag`, `emission_scale`, `radius_lower`, `radius_upper` (`SS2G_instance_SS.yaml`).
- SU2G: `using_GMI`, `disable_emissions`, `volcano_srcfilen_degassing`, `volcano_srcfilen_explosive`, `aircraft_fuel_emission_factor`, `so4_anthropogenic_fraction`, `aviation_vertical_layers`, `DIURNAL_BIOMASS_BURNING` (`SU2G_GridCompMod.F90`, `SetServices`, `Initialize`).
- CA2G, NI2G: not built; their keys are in the MAPL2 `.rc` files and sources.
- `AMIP/` and `AMIP.20C/` subdirectories of each child hold variants of the rc and yaml files (for example volcano source files in SU2G). `SU2G_GridComp/AMIP/SU2G_GridComp_ExtData.yaml` differs from the MAPL2 line (five lines removed). Selection of a variant is done outside this repository.
- Resource lookup on this line: `MAPL_GridCompGetResource(gc, "<key>", value, default=...)`; the lookup order across component, type and parent is defined by MAPL3, not by this repository. *Unverified:* how a child finds the parent's wavelength keys.

- MAPL (state, spec, child, connection, resource, ACG; imported through `use MAPL, only: ...` and `use MAPL_Constants`), ESMF, NetCDF Fortran, OpenMP (not with NAG) (`ESMF/GOCART2G_GridComp/CMakeLists.txt`).

On this line the routine reads `RUN_AT_INTERVAL_START` with `MAPL_GridCompGetResource` and no longer checks it against a per-child `p:` key. *Unverified:* that the alarm's only consumer is the oxidant recycling described in the source comments.
- Outside the repository: `GEOS_ChemGridComp.F90` (MAPL2 code, not compiled on this line); the regression cases supply imports from a data component and ExtData files named in each child's `*_GridComp_ExtData.yaml`.
- `Process_Library` is also linked by `@GMI` (`ReadPointEmissions`; `@GMI` is not built on this line).

## 8. Known traps
- **Run phase names.** Phases are registered and run by name (`Run1`, `Run2`, `Run0`), not by number. The parent's `run2` runs child `Run0` first, then `Run2`, so klid zeroing happens at every `Run2` call. The parent has no alarm check on this line.
- **Data instances are unsupported.** Creating a child whose name contains `data` stops in `SetServices` (`_FAIL`). The parent's loops still skip names containing `data` (`index(child_name, "data")`).
- **Single-instance assumptions.** The parent asserts at most one active NI instance (`SetServices`), and `run2` reads `NI%instances(1)` for `nifactor` after a size check. The unguarded `instances(1)` accesses for DU, SS and SU belong to the NI connection block of `SetServices`, which is commented out on this line, so they are not live. The `PSO4` re-export dereferences `SU%instances(1)` after a size check.
- **Order of instances.** DU, SS, SU (CA and NI would follow); `AERO` and `AERO_DP` contents follow this order (`create_instances_`, `add_aero_states_`). *Unverified:* whether active-before-passive ordering is still enforced in `setup_instances__`.
- **`AERO_DP` bin counts** must match the Surface component's expectation or Surface stops (see [repository architecture](../../docs/ARCHITECTURE.md), section 5.6). MAPL2-line behaviour: the SU2G data instance appends only bin `003` (sulfate) to `AERO_DP` (`SU2G_GridCompMod.F90`, `append_to_bundle`). On this line that branch is unreachable, because data instances `_FAIL` in `SetServices`.
- **Fields in `AERO` are allocated by the child.** `add_aero` creates the `AERO` fields for a child with `MAPL_FieldCreate` on the geometry and adds them to the child's `<name>_AERO` state (`ESMF/Shared/Chem_AeroGeneric.F90`, `add_aero`); the parent then adds each child state into its own `AERO` state (`GOCART2G_GridCompMod.F90`, `add_aero_states_`). Consumers reach species data by iterating the nested child states, not by a flat field list.
- **Wavelength lists.** `TOTANGSTR` needs 550 nm, backscatter exports need 532 nm in the lists in `GOCART2G_GridComp.yaml`; removing them fails `run2`. The parent reads `aerosol_photolysis_wavelengths_in_nm_from_LUT` while the YAML key is `aerosol_photolysis_wavelength_in_nm_from_LUT` (section 10).
- **`nifactor` in the parent.** Sulfate particulate-matter sums in parent `run2` use `nifactor` (132.14/96.06) unless the first NI instance is active and not data-driven, then 1.0 (`GOCART2G_GridCompMod.F90`, `run2`). On this line NI instances are always inactive, so `nifactor` stays 132.14/96.06.
- **Resource variants.** Files under `AMIP/`, `AMIP.20C/` and the base directory define the same keys with different values; which set is used is decided outside this repository. Both `.rc` (MAPL2) and `.yaml` (MAPL3) versions of the instance files sit side by side in the ported children; the ported parent reads only the YAML.
- **Threads.** Workspaces are per thread (`workspaces(0:num_threads-1)`); *Inferred:* shared module-level state added to a child would be unsafe if threads are used, although the parent's `use_threads` handling is commented out on this line.

## 9. Decisions
Recorded in [decisions.md](../../docs/decisions.md): one child per instance; `AERO` as a state of methods; shared environment type `GA_Environment`; `Process_Library` separated from MAPL state; hand-ordered coupling of NI to sibling instances; data instances by name; dual run-phase protocol; ACG for state specs. Two decisions are specific to this line: unported species are ignored, and advection by `TRADV` subscription. All are author decisions for review.
